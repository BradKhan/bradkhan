# Build queue

The goal is **credible, visible software**, not a mountain of speculative repositories. Promote an entry only when a tiny real demonstration can be shipped.

## Promotion gates

1. **Source reality:** check canonical upstream, license, installation method, security notices and activity at a recorded date.
2. **Technical boundary:** decide which features are reused versus original, and test integration compatibility.
3. **One heroic demo:** show an end-to-end user outcome in 15–60 seconds. No invented metrics or screenshots.
4. **Portability:** include one export path and no mandatory lock-in when feasible.
5. **Distribution:** identify three existing communities with a reason to use or share it; approach maintainers respectfully.
6. **Publication:** publish code, tests, concise architectural notes, source credits, limitations and demo proof.

Don't promote a candidate solely because its source repositories are popular.
