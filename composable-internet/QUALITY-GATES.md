# A deterministic path toward a genuinely exceptional GitHub portfolio

**Definition:** 10/10 is an ambition, not a score that can be established by an agent looking at its own output. This plan uses explicit gates, external review and actual usage to prevent self-congratulation.

## Positioning and design

- [x] **G1 / Accurate positioning:** Primary identity is Entrepreneurial Technologist; entrepreneurship, technical leadership and philosophy appear without invented affiliations or titles.
- [x] **G2 / Reduced visual noise:** A single outlined-name SVG replaces the previous multi-message banner. It uses no font download, third-party image, animated counter or gratuitous device graphics.
- [ ] **G3 / Visual acceptance:** Confirm GitHub's rendered desktop and mobile profile, accessibility, scaling, layout and typography against the *actual* client-approved reference. The specified reference URL was not accessible in this working session. This is not approved solely because a local SVG preview exists.

## Editorial and technical integrity

- [x] **G4 / Truthful evidence levels:** Clearly separate public software, templates, external source references and proposed compositions.
- [x] **G5 / Source provenance:** Structured source registry includes origin and review level, and does not take credit for saved upstream repositories.
- [x] **G6 / Real taxonomy:** Use eight cross-project domains; individual ideas are not each given their own category.
- [ ] **G7 / Source audit:** Verify canonical upstream URL, actual license, current security condition, last release, runtime requirements and incompatibilities for all *featured* source projects. Inventory-only records must remain explicitly unverified.
- [ ] **G8 / Functional builds:** At least three compositions reach reproducible proof-of-concept status with code, installation steps, independent tests and genuine visual media. None has passed this gate.
- [ ] **G9 / Human usability:** Three target users, at least one each from development, venture building and an independent generalist audience, can explain and use a featured resource without coaching.
- [ ] **G10 / Distribution and external response:** Produce a documented release kit for three working projects and record real references, adoption or valuable maintainer feedback. No invented follower or traffic milestones.

## Operational rules

The tests in `.github/workflows/profile-catalog.yml` check the registry's *structure* only. They are not a substitute for G3, G7, G8, G9 or G10.

Do not mark an unchecked gate complete merely because documentation has been published. When external testing is absent, report the gate as open.

## Review rhythm

- With every catalog change: run `python3 composable-internet/scripts/validate.py`.
- With every profile design change: review the rendered dark/light GitHub surfaces at desktop and mobile widths, using real screenshots.
- Before elevating a composition to a release: add an exact implementation URL, commit, test command, output evidence and known limitations.
- Before outreach: independently assess whether the project provides a genuinely new user outcome beyond its upstream ingredients.

## Priority queue

1. Accurate profile identity and a restrained visual system.
2. A source library with provenance, credible taxonomy and usable search.
3. A working proof-of-concept chosen for *exceptional result per unit of engineering effort*.
4. A finished public demonstration and source-backed write-up.
5. Repeat with evidence from actual users and external maintainers.
