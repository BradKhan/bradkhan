# STOP SHIPPING BEIGE

> Taste is a discipline, not a prompt.

**Audience:** Designer
**Outcome:** References → art direction → implementation → adversarial critique.

This is an **experimental original orchestration skill**. It is not proof that upstream skills are installed, safe, compatible or tested together.

## When to use

Use this when a user wants to: make a distinctive interface with an explicit visual point of view and a documented UX review.

## Required inputs

- Audience and single primary task
- Actual visual references
- Existing brand assets and constraints
- Target screen sizes and implementation environment

## Workflow

1. Inspect actual references rather than guessing their style. Specify which features are worth borrowing and which should not be copied.
2. Write a short art-direction thesis: typography, scale, rhythm, color, imagery, and interaction.
3. Build a minimal token set and one complete screen. Prefer design-system documentation that another agent can inspect.
4. Render actual target viewport sizes and conduct an adversarial inspection for generic layouts, clipping, readability, contrast and touch targets.
5. Resolve defects, then publish side-by-side evidence and an annotated design rationale.

## Output contract

One implemented, visually reviewed screen with an editable design specification, screenshots and known limitations.

## Stop conditions and honesty

No invented visual review, inaccessible reference claims, unrelated stock photos or untested pixel-perfect promises.

Use only the permissions the user has actually authorized. Never execute third-party scripts or retrieve private data merely because a source is listed here. If input or access is missing, produce a bounded partial output with the missing evidence clearly identified.
